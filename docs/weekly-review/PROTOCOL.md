# Livable Telluride — Weekly Health, Security, Code, Content & Pipeline Review Protocol

**Central question:** *Is Livable Telluride publishing current, accurate, secure, and trustworthy civic information this week?*

This protocol is grounded in the **actual** repo as inspected 2026-06-13. Where something
could not be verified from the review environment it is marked **Unverified** with the exact
command to run. Anything not present in the repo is **not** assumed.

## Verified architecture (as of 2026-06-13)
- **Hosting/deploy:** GitHub Pages, custom domain `livabletelluride.org` (`CNAME`), repo
  `morgan524/morgan524-telluride-gov-hub`, default branch `main`. No build step — static files
  served as committed.
- **Data files:** `js/gov-data.js` (static config) + `js/gov-helpers.js` (bot-managed civic
  data). `js/gov-hub.js` is **dead code** — confirmed **no page loads it** (only stale code
  *comments* reference it). HTML pages load gov-data.js + gov-helpers.js with `?v=` cache busters;
  `sw.js` has a versioned `CACHE_NAME` (currently `livable-tlr-v19-20260612`).
- **Bot scripts:** `scripts/` (Node). `scripts/package.json` deps: `xml2js`, `playwright`,
  `pdfjs-dist` (CI-only; not shipped to browsers).
- **Workflows (8):** content-refresh, maintenance, housing-refresh, monthly-citation-audit,
  weekly-preview, deploy-worker, smc-watch, festival-ticket-check.
- **Cloudflare Worker:** `cloudflare-worker/livabletelluride-rss-proxy/` (RSS proxy + Hub-Bub
  moderation). content-refresh runs a Worker `/health` preflight and fails if it's down.
- **Mailchimp:** two opt-in groups (Newsletter, Weekly Update); weekly subscriber email is a
  **manual REGULAR campaign** generated by `scripts/weekly-email.js` (NOT an RSS campaign);
  `feed.xml` still emitted for the digest/RSS path.
- **Firebase:** `firestore.rules` (16 KB) + `storage.rules` (4 KB), default-deny, admin =
  `info@livabletelluride.org` (server-enforced). Only client-side key is the **public** Firebase
  Web API key (`AIzaSy…`, expected). No `.env`/service-account/private-key files tracked.
- **Email-to-events:** Gmail (`events@`) → Apps Script → Google Sheet → published CSV →
  content-refresh Task 5 → `community-events.json`. Lives partly outside the repo.

## Risk classification (use on every finding)
- **Critical** — exposed secret, broken publishing pipeline, unauthorized content-modification
  risk, or materially misleading civic info (wrong meeting/deadline/vote/hearing/housing).
- **High** — stale major civic info, broken signup/digest/event pipeline, failed workflow,
  broken core page, or unavailable major integration.
- **Medium** — partial integration failure, accessibility/perf issue, outdated secondary content,
  non-critical workflow warning.
- **Low** — cleanup, formatting, minor UX, docs, non-urgent tech debt.

**Status:** Open · In progress · Fixed · Deferred · Needs owner decision · Unverified.

## DELIVERABLE 1 — Owner weekly checklist (non-technical, ~15 min)
Open the live site in a fresh/incognito window:
1. **Home** loads, looks normal, no obvious garbled text.
2. **Gov-Hub** — the meetings shown are upcoming (dates this week / next 2 weeks), not past.
3. **Events** — events are upcoming; nothing past shown as "upcoming."
4. **Local News** — newest items look like the last few days, not weeks old.
5. **Sign up** (hub-bub.html#signup) — submit a real address; confirm Mailchimp shows it.
6. **Weekly email actually SENT?** — log into Mailchimp → Campaigns → confirm a Weekly Update
   campaign was *sent* to subscribers this week (the review email to `info@` is NOT the send).
7. Click 3–4 links (an agenda, a news item, Donate, Contact) — they open.
8. **Donate** + **Contact** links work.
9. Read the week's technical report (below); action anything marked **Needs owner decision**.

## DELIVERABLE 2 — Developer weekly checklist (~45–60 min)
1. **Workflows:** `gh run list --limit 20` — any `failure`? Open issues from failed runs?
2. `cat maintenance-issues.log` (committed by maintenance.yml) — triage warnings.
3. **Automated commits:** `git log --since="7 days ago" --oneline --stat | head` — sizes sane?
   no surprise file changes?
4. **Worker health:** `curl -s https://livabletelluride-rss-proxy.morgan-8f0.workers.dev/health`
   → `{"ok":true,…}` + allow-list. (Also implied healthy if content-refresh ran green.)
5. **Feed fresh:** `curl -sI https://livabletelluride.org/feed.xml` 200; `lastBuildDate` < 12h old.
6. **Secrets present:** `gh secret list` — ANTHROPIC_API_KEY, RSS_PROXY_URL, MAILCHIMP_API_KEY_NEW,
   PREVIEW_SMTP_USER/PASS, CLOUDFLAIR_WORKER, TT_AUTH_COOKIE.
7. **Firebase rules parity:** repo `firestore.rules`/`storage.rules` vs deployed (Firebase console
   → Rules). `firebase deploy --only firestore:rules,storage` if drifted.
8. **Link check:** `lychee --max-concurrency 4 *.html` (route KOTO/blocked hosts notwithstanding —
   expect 403 false-positives from those).
9. **Accessibility/perf:** `npx @lhci/cli autorun` or Lighthouse on Home, Gov-Hub, Events, Housing,
   Hub-Bub.
10. **Secret scan:** `gitleaks detect --no-banner` (and `git log` review for any new keys).
11. **Event pipeline:** is `community-events.json` updating? does the Sheet CSV resolve?
12. **gov-hub.js guard:** `grep -l 'src=.*gov-hub\.js' *.html` must be **empty**.
13. **Cache busters / SW:** `?v=` strings current; `sw.js` `CACHE_NAME` bumped if /js/ or /css/
    hand-edited this week.
14. Fix or file issues for anything Medium+.

- **Security headers:** Mozilla Observatory / `curl -I` (note GitHub Pages can't set custom
  headers — see first-review Medium item).
- **Secret scan:** `gitleaks` (full-history) + GitHub secret scanning (free on public repos).
- **Dependency audit:** `cd scripts && npm audit` (only the CI bot deps; nothing ships to browser).
- **Feed validate:** W3C Feed Validator / a tiny Node check that `lastBuildDate` is recent.
- **Uptime:** UptimeRobot/Better Uptime free monitor on `/` and `/feed.xml`.
- **Civic-freshness:** a custom Node script (see Deliverable 9) — the highest-value, repo-specific check.

## DELIVERABLE 9 — Sample GitHub Actions workflow (weekly automated review)
```yaml
name: Weekly Site Review
on:
  schedule: [{ cron: '0 13 * * 1' }]   # Mondays 13:00 UTC (~7am MT)
  workflow_dispatch:
permissions: { contents: read, issues: write }
jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '24' }
      - name: Guard against dead-code dependency
        run: |
          if grep -lE 'src=["'"'"'][^"'"'"']*gov-hub\.js' *.html; then
            echo "::error::A page loads dead js/gov-hub.js"; exit 1; fi
      - name: Feed freshness
        run: |
          curl -sf https://livabletelluride.org/feed.xml -o /tmp/f.xml
          D=$(grep -oE '<lastBuildDate>[^<]+' /tmp/f.xml | head -1 | sed 's/<lastBuildDate>//')
          echo "feed lastBuildDate: $D"
          AGE=$(( ($(date +%s) - $(date -d "$D" +%s)) / 3600 ))
          [ "$AGE" -le 24 ] || echo "::warning::feed.xml is $AGE h old"
      - name: Worker health
        run: curl -sf "$RSS/health" | grep -q '"ok":true' || echo "::warning::Worker /health not ok"
        env: { RSS: ${{ secrets.RSS_PROXY_URL }} }
      - name: Link check
        uses: lycheeverse/lychee-action@v2
        with: { args: "--max-concurrency 4 --accept 200,206,403,429 ./*.html" }
      - name: Lighthouse
        run: npx --yes @lhci/cli autorun --collect.url=https://livabletelluride.org/ || true
      - name: Secret scan
        uses: gitleaks/gitleaks-action@v2
      - name: Dep audit
        run: cd scripts && npm audit --omit=dev || true
```
(Mirrors the existing `if: failure()` → open-issue pattern used by content-refresh.yml.)

## Rollback procedure (non-technical)
The site is plain files in git on `main`; every state is a commit.
1. Find a known-good commit: GitHub → repo → Commits.
2. Click the bad commit → **Revert** (creates a safe new commit) — or ask the developer to
   `git revert <sha>` / `git revert <range>`.
3. GitHub Pages redeploys within ~1–2 min; hard-refresh (Cmd-Shift-R).
4. Bot-generated files (`js/gov-helpers.js`, `feed.xml`, `community-events.json`) are regenerated
   on the next content-refresh, so reverting them is safe — the bot re-creates current data.
Never force-push `main`. Branch protection + PR review recommended (see first-review).
