Design notes — extraction strategy + filter taxonomy

1. What's in the card and why

The card is built around facts only — values that any system could read off the published notice (dates, addresses, names, file numbers, contact info). Facts are not copyrightable; the publisher's prose is. The plain-English summary at the top is a short, original synthesis (1–2 sentences) describing what the notice is for, not a paraphrase of the source.

3. Extraction strategy (when piping from Column)

  • Type / category — derive from the notice's title + body using a regex+keyword classifier. Most notices self-identify in the first 1–3 lines ("CONDITIONAL USE PERMIT APPLICATION", "NOTICE TO CREDITORS", "WATER COURT RESUME").
  • Entity — usually printed at the top or in a "Filed by:" line. Pattern-match against a known list of local agencies (Town of Telluride, SMC Clerk & Recorder, Water Court Div. 4, etc.).
  • Address — regex for street numbers + street suffix (Ave, St, Rd, Hwy) inside the body, then geocode via Nominatim/OpenStreetMap (free) or Google Geocoding (paid, more accurate). Cache the lat/lng so the map iframe loads instantly.
  • Hearing date/time — regex for "Wednesday, May 21, 2026" + "6:00 PM"-style strings; cross-validate against known meeting cadences in Gov-Hub (BOCC every other Tuesday, P&Z 2nd Wed, etc.).
  • Comment deadline — usually phrased "written comments must be received by..." → regex for the date pattern.
  • File number — regex for ALL-CAPS prefix + digits (e.g., CUP-2026-0142, 2026-CV-0034).
  • Summary synthesis — Claude API call with the body text + extracted facts; prompt asks for a 1–2 sentence factual summary (no editorial language, no copying source phrasing). Cache by Column notice ID so we only spend tokens once per notice.

4. Action buttons (per card)

  • Read Full Notice → links to the Column source page (always).
  • Add Hearing to Calendar → only if hearingDate present. Generates Google Calendar quick-add URL with title, location, time, link to source.
  • Submit Comment → only if commentChannel present. mailto: when channel is email; opens form when channel is URL.
  • Open in Google Maps → in the map column, only if location present.

5. "Near me" filter (suggested)

Once notices have geocoded addresses, the most valuable filter is distance from user's address. The sidebar already has a "Within 0.5 mi of my address" placeholder. Backend: store user's address in localStorage (already done elsewhere on the site for events-near-me); compute distance per notice and sort/filter.
